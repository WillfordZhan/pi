# Pi 教学式开发 Skill 设计

## 目标

在 Pi 与 Java Runtime 的日常讨论和定制开发中，同时完成工程任务与源码学习。所有讲解必须建立在当前工作区的代码事实之上，帮助不熟悉前端、TypeScript 和 Pi 内部实现的 Java 后端开发者理解模块职责、端到端调用链及设计原因。

## 方案

新增用户级 Codex `learn-pi-by-doing` Skill，并在 Pi 根目录 `AGENTS.md` 中保留简短的强制触发规则：

```text
AGENTS.md
~/.codex/skills/learn-pi-by-doing/SKILL.md
~/.codex/skills/learn-pi-by-doing/agents/openai.yaml
```

`AGENTS.md` 只负责规定何时必须使用 Skill，不复制具体教学流程。用户级 Skill 负责代码取证、讲解深度选择和输出结构，避免项目规则继续膨胀；该 Skill 不随 Pi 仓库分发。

## 触发范围

- 涉及 Pi 或 Java Runtime 的功能讨论、概念解释和简单问答时，使用 B 层标准讲解。
- 涉及源码分析、功能设计、定制开发、问题诊断或代码评审时，在 B 层基础上增加 C 层源码导读。
- 用户显式要求更浅或更深的讲解时，以用户要求为准。

## 代码事实约束

执行讲解前先检查与问题直接相关的入口、调用方、实现、关键类型和外部边界。不得仅凭模型记忆、文件名、README 或历史设计文档推断当前行为。

回答中明确区分：

- 当前代码直接支持的事实；
- 文档描述但尚未由实现验证的内容；
- 基于代码事实作出的工程推断；
- 尚未实现的建议方案。

关键结论引用具体文件、函数、类或类型；行号只在有助于快速定位时提供。无法从当前代码确认的内容必须标记为“尚未核实”，不得补全成确定结论。

## B 层：标准教学

保持结论优先，并按任务需要覆盖：

1. 本次问题涉及的模块及其职责；
2. 从输入入口到最终结果的端到端链路；
3. 对 Java 后端开发者有帮助的概念类比；
4. 当前实现采用这种设计的代码依据；
5. 本次问题或改动在 Pi 整体链路中的位置；
6. 建议继续阅读的少量关键文件。

简单问题不强制输出固定标题，也不展开与当前问题无关的模块。

## C 层：源码导读

在 B 层基础上进一步说明：

1. 入口函数以及真实调用顺序；
2. 关键类、函数、类型及各自职责；
3. 请求、状态和数据在各层之间如何变化；
4. 关键分支、错误路径和外部系统边界；
5. 实施前后的链路差异及设计原因；
6. 面向初学者的源码阅读顺序。

C 层聚焦当前任务的最短完整链路，不进行无关的全仓库导览。

## Blog 沉淀提醒

当一次任务实际使用 Pi 原生模块，或对 Pi 基础模块、Java Runtime 适配层进行定制修改时，在任务交付阶段提醒一次是否将本次学习内容沉淀为 Blog。提醒应基于本次已核实的代码事实，简要指出适合记录的主题，不使用固定模板虚构学习成果。

纯业务讨论、未触及 Pi 实现的修改或同一任务的中间进度不触发提醒。未经用户确认，不创建、不修改也不发布 Blog。

## Skill 内容边界

Skill 只保存稳定的取证流程、深度选择规则和输出要求，不保存容易随代码变化而过期的静态模块地图。每次任务都从当前工作区重新追踪实现。

首版不添加脚本、额外参考文档或资产。现有文件检索和源码阅读工具足以完成工作；出现稳定、重复且无法靠指令可靠完成的流程后再考虑扩展。

## 验证

- 使用 Skill 校验脚本检查目录名、YAML frontmatter 和必填字段。
- 检查 `AGENTS.md` 仅包含触发规则，没有复制 Skill 正文。
- 检查 Skill 对简单问答选择 B，对源码分析和定制开发选择 B+C。
- 检查回答要求明确区分代码事实、文档描述、工程推断与建议方案。
- 检查实际使用或修改 Pi 模块的任务在交付时提醒一次 Blog 沉淀，其他任务不提醒。

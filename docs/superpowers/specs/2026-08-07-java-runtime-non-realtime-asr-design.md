# Java Runtime 非实时语音转写设计

## 目标

在 Pi Runtime Management Console 增加“录音转文字”能力。用户完成录音后，浏览器把音频发送给 Java AI Gateway；Gateway 调用阿里云百炼的非实时 `fun-asr-flash-2026-06-15`，并把转写文本返回给浏览器。浏览器仅将文本填入现有消息输入框，用户可修改并自行确认发送；Pi Runtime 和 LLM 始终只接收用户最终确认的文字。

这项能力服务于 ERP 数字员工：语音只是输入方式的补充，不能绕过用户对业务指令的确认，也不能让音频原文进入 Agent 会话、工具调用或会话历史。

## 已确认约束

- 采用阿里云百炼。
- 采用非实时识别，不建设实时 WebSocket 流式转写。
- 录音结束后才提交转写；转写结果先填入输入框，用户确认后才按既有 SSE 链路发送给 Pi。
- 第一版不接入 OSS，不保存音频文件，不支持历史音频回放。
- 第一版只改 Management Console 与 Java AI Gateway；不改 Pi Runtime 的会话协议和 LLM Provider。
- 浏览器录音最长 5 分钟；Java 对原始上传体限制为 7 MiB。前者由浏览器计时自动停止，后者是 Java 的权威容量边界。因为百炼要求 Base64 后的音频不超过 10 MiB，7 MiB 原始音频编码后仍留有 JSON 传输余量。

## 方案选择

采用“浏览器完整录音 + Java 同步 HTTP 转写”的方案：

```text
Management Console
  -> MediaRecorder 录制 WebM/Opus
  -> POST /api/ai/asr/transcriptions（multipart）
  -> Java 校验、转为 Base64 Data URI
  -> 阿里云百炼 fun-asr-flash HTTP
  -> { text }
  -> 写入 Management Console 现有输入框
  -> 用户修改 / Enter 或发送按钮
  -> 原有 /api/ai/conversations SSE
  -> Pi Runtime
  -> LLM / ERP MCP 工具
```

不采用以下方案：

- **实时 WebSocket ASR**：当前交互不展示逐字结果，增加双向连接、音频分片和中断状态不会提升业务价值，且价格更高。
- **浏览器直连阿里云**：会暴露百炼 API Key，无法接受。
- **上传 OSS 后异步任务转写**：短指令不需要持久文件与轮询任务；会额外引入对象权限、清理和状态机。
- **把音频转给 Pi/LLM**：与“人工确认后才执行 ERP 指令”的边界冲突，且需要让每个 Provider 支持音频输入。

## Management Console

在线调试输入区使用浏览器原生 `MediaRecorder`，不新增录音 SDK：

1. 点击“开始录音”后请求麦克风权限，按钮切换为“结束录音”，同时显示录音时长。
2. 到达 5 分钟时自动结束录音并提交；用户也可以主动结束。
3. 结束后将生成的一个音频 Blob 作为 `audio` 字段提交给 `/api/ai/asr/transcriptions`；转写期间禁用录音按钮，消息发送按钮不受影响。
4. 成功时将返回文本追加到现有输入框：已有文字保留，并以换行分隔；不会自动发送、清空图片或创建 Pi 会话。
5. 失败时保留用户当前输入及图片，只提示错误；音频 Blob 在本轮结束后释放，不在前端缓存或重传。

浏览器只能录制其支持的格式，优先选择 `audio/webm;codecs=opus`；若浏览器不支持 `MediaRecorder` 或没有可用 MIME，则明确提示该浏览器不支持录音。浏览器侧先校验空文件、大小和时长；Java 对单文件、非空和 7 MiB 容量执行权威校验，百炼再根据真实音频内容完成最终格式与时长校验。

## Java AI Gateway

新增独立接口，不复用会话创建或图片上传接口：

```text
POST /api/ai/asr/transcriptions
Content-Type: multipart/form-data

audio: 一个音频文件

200: { "text": "转写结果" }
```

Controller 仍通过既有 `AiContextResolveService` 解析登录人。转写接口不创建会话、不调用 Pi Runtime，也不将转写文本写入 Java 会话表；解析登录人只用于权限边界、审计日志中的 traceId，以及为后续限流预留统一入口。

Java 服务层负责以下通用职责：

1. 校验单文件、非空、最大 7 MiB；MIME 仅作为协议提示，不能替代百炼对真实音频内容的最终校验。
2. 读取受大小限制的音频字节，构建 `data:<mime>;base64,...`。7 MiB 原始音频的 Base64 约 9.4 MiB，满足百炼 10 MiB 的 Data URI 上限，也不需建设 OSS。
3. 使用 Java 现有 `HttpURLConnection` 调用百炼 HTTP API，并设置 `Authorization: Bearer <API_KEY>`；不新增 SDK 或 HTTP 依赖。
4. 从百炼成功响应提取最终 `text`，空文本作为不可用转写结果返回给前端。
5. 不记录 API Key、Authorization、完整音频字节、Base64 或转写全文；错误日志只保留状态码、模型名和 traceId。

百炼连接地址、API Key、模型名、连接/读取超时和上传大小均通过 `ai.asr.*` 配置提供。密钥只从部署环境变量或 Nacos 密钥配置注入，绝不写入仓库的 `application.yml`、前端构建产物或浏览器。

第一版使用 `fun-asr-flash-2026-06-15`。它接受短音频的 URL/Base64 输入，支持传入 ERP 业务词汇的上下文增强；第一版固定传入通用业务上下文，不预置面向某个客户或某条问题的硬编码词表。后续出现稳定且可复用的 ERP 专有名词集合时，再通过配置维护上下文文本或热词表。

## 错误边界

- `400`：缺少音频、空文件、浏览器不支持录音或无可用转写文本。
- `413`：原始音频超过 7 MiB。
- `422`：百炼拒绝音频内容或无法完成识别。
- `502`：Java 无法连接百炼、百炼返回网关错误或响应结构不符合预期。
- `504`：百炼调用超时。

前端根据响应展示可读错误，不吞掉已有文字、图片或当前会话。录音和转写期间不自动发送文本；正在进行 Pi SSE 对话时沿用现有“请求中禁用附件操作”的交互，避免两份大 multipart 请求竞争同一个调试界面状态。

## 泛化与边界评估

- 接口表达的是通用“音频转文字”能力，不与任意 ERP Tool、业务字段、具体口令或页面流程绑定。
- Agent 的输入边界保持文字；更换 Qwen 或 OpenAI Codex 模型不需要改动语音转写协议。
- 第一版有意不保存音频。若以后需要会议纪要、质检或审计录音，再独立建设“对象存储 + 生命周期 + 授权 + 异步长音频任务”，不要把这些职责塞进即时指令入口。
- 5 分钟和 10 MiB 是第一版可观测的容量上限；若未来真实数据表明较长音频有价值，再切换到百炼文件转写与 OSS，而不是放宽当前同步接口的内存边界。

## 验证

### Java 聚焦测试

- 合法小音频可以被编码为 Data URI，并正确解析百炼成功文本。
- 缺失、空文件、超 7 MiB、非法 MIME 分别返回预期状态。
- 百炼的认证失败、超时、错误响应和空文本被转换为稳定的客户端错误，且日志不含音频/Base64/API Key。
- 配置缺失时启动不泄露密钥，调用时返回明确的服务端配置错误。

### Management Console 验证

- Chromium 中允许麦克风权限，录音结束后文本填入输入框，不自动发送。
- 用户可修改转写文本，再通过既有 SSE 成功发给 Pi。
- 已输入的文字、已选择的图片在成功和失败时都保持正确。
- 拒绝权限、浏览器不支持录音、网络失败、超时和超限音频都有可理解提示。

实现代码后，Pi 仓库运行 `npm run check`；Java 工程运行受影响的聚焦测试。不会为验证转写额外调用真实付费 API，外部 HTTP 以本地 Mock 服务覆盖。

## 第一版明确不做

- 实时逐字转写、VAD、暂停续录、音频波形和录音回放。
- OSS 上传、音频历史、下载、审计留存或异步长文件转写。
- 自动发送转写结果、自动执行 ERP Tool，或让音频直接进入 Pi 会话。
- 增加第三方浏览器录音库、阿里云 Java SDK 或新的 HTTP 客户端依赖。

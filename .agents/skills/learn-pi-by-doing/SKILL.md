# Pi 教学式开发

在完成任务的同时帮助用户理解 Pi。保持结论优先，只讲与当前问题有关的最短完整链路。

## 先核实代码

1. 检查相关入口、调用方、实现、关键类型和外部边界；源码分析和修改前读取涉及文件的完整内容。
2. 以当前实现为准，不根据模型记忆、文件名、README 或历史设计文档推断行为。
3. 关键结论引用具体文件与符号，必要时提供行号。无法确认的内容标记为“尚未核实”。
4. 明确区分代码事实、未由实现验证的文档描述、工程推断和建议方案，不把拟议设计描述成现有能力。

## 选择讲解深度

所有相关任务使用 B 层。源码分析、功能设计、定制开发、问题诊断和代码评审在 B 层基础上增加 C 层。用户指定深度时以用户要求为准。

### B 层：标准教学

按当前问题需要说明：

- 涉及模块及职责；
- 从输入到结果的端到端链路；
- 帮助 Java 后端开发者理解的概念类比；
- 设计原因及其代码依据；
- 当前问题或改动在 Pi 整体链路中的位置；
- 值得继续阅读的少量关键文件。

简单问题不要强制套用固定标题，也不要展开无关模块。

### C 层：源码导读

追加说明真实入口和调用顺序、关键类型、数据与状态变化、重要分支、错误路径和外部边界。修改前讲清现有链路，修改后讲清新链路、差异和原因，并给出适合初学者的源码阅读顺序。

只追踪当前任务的最短完整链路，不进行无关的全仓库导览。

## 提醒 Blog 沉淀

当任务实际使用 Pi 原生模块，或定制 Pi 基础模块、Java Runtime 适配层时，在最终交付中提醒一次是否将本次学习记录为 Blog，并根据已核实代码指出建议主题。

纯业务讨论、未触及 Pi 实现的修改和中间进度不提醒。未经用户确认，不创建、修改或发布 Blog。
